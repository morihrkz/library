# library

AI と共同で執筆した論考を公開する GitHub Pages サイトのリポジトリ。

- 公開 URL: https://morihrkz.github.io/library/
- 公開ブランチ: `main`(ブランチを切らず直接コミットする運用)

## 構成

ビルドツールは使わず、静的 HTML をそのまま GitHub Pages が配信する。

- `index.html` — ポータルページ。次の 4 節で構成する。
  - 01 書架 — 全記事を背表紙として一つの本棚に並べる。色は分野、背の厚さは本文の文字数を表す。ホバーで書見台に概要を表示する。
  - 02 読み筋 — 独学をめぐる 4 本の記事を、読む順序つきで紹介する特集。
  - 03 新着 — 追加日の新しい 4 本。
  - 04 目録 — 分野別の全記事一覧。検索欄と分野の絞り込みボタンを持つ。
- `*.html`(上記以外) — 個々の論考。すべてルート直下にフラット配置。
- `future-article-themes.md` — 次に書くテーマの検討メモ。既存記事の分類・関心の構造から、まだ手つかずの角度を洗い出したもの。着手・完了のたびに更新する。
- `public_URL.txt` — 公開 URL とリポジトリ URL のメモ(`.gitignore` 対象、リポジトリには含まれない)。

### `index.html` の仕組み

目録(04 節)の各項目 `<li class="entry">` が唯一のデータ源である。書架の背表紙、分野の仕切り札、上部の統計(記事数・分野数・総文字数・通読の目安)、各分野の本数、新着の 4 本は、すべてページ読み込み時に JavaScript が目録から組み立てる。そのため、記事の追加・削除で手作業の更新が要るのは、目録の項目と「最終更新」の日付だけである。

## 記事の分類(8 分野)

`index.html` の目録の分野(`<section class="group">`)と対応する。新しい記事を追加する際は、内容に最も近い分野へ収める。

1. 比較政治学・時事分析
2. 心理学
3. 哲学・論理学
4. 自然科学
5. 歴史・宗教・教育
6. テクノロジー・産業分析
7. 社会評論・生き方・文章技法
8. 健康・生活

分類は主観的な整理であり、複数分野にまたがる記事を便宜的に一つの分野へ収めている場合がある(`index.html` 末尾の note を参照)。分野ごとの色は CSS 変数 `--c1` 〜 `--c8` で定義している。分野を増やす場合は、色の変数(淡色の文字 `#f3f4ef` とのコントラスト比 4.5 以上)と `.c9` のようなクラスも追加する。

## 新規記事を追加する手順

1. 記事の HTML ファイルをリポジトリのルート直下に追加する。
2. `index.html` の目録で、該当分野の `<ol class="entries">` の末尾に、次の形式の項目を 1 行追加する。

   ```html
   <li class="entry" data-date="2026-09-25" data-len="6832"><a href="file-name.html"><span class="e-kicker">記事のキッカー</span><span class="e-title">記事タイトル</span><span class="e-desc">一文の概要。</span><span class="e-meta">約 0.7 万字 ・ 読了目安 11 分</span></a></li>
   ```

   - `data-date` — 追加日(`YYYY-MM-DD`)。新着の選定と、書架の新着印(追加日が新しい順に 2 日分)に使う。
   - `data-len` — 本文の文字数。参考文献欄(`<div class="refs">`)より前の可視テキストから、空白・改行を除いて数える。背表紙の厚さと総文字数の計算に使う。
   - `e-kicker` — 記事冒頭のキッカー(`class="kicker"`)の文言をそのまま写す。
   - `e-meta` — 文字数を万字単位(小数第 1 位)で、読了目安を `data-len ÷ 600` を四捨五入した分数で書く。
3. ページ上部の「最終更新」の日付(`<span class="updated">`)を更新する。
4. 分野の記事構成が変わった場合は、`future-article-themes.md` の該当クラスタの記述も見直す。

記事数・分野の本数・書架・新着は自動で反映されるため、手で書き換えない。

## 記事の統合・改題・削除

過去に複数記事を 1 本へ統合した例がある(例: `envy-comparison-theory.html` と `ranking-formation-structure.html` を `social-comparison-theory.html` へ統合。また、詳論記事 `nanto-rokushu-buddhism.html` を通史記事 `japanese-buddhist-sects.html` の 1 章へ統合)。この場合は、統合元ファイルを削除し、 `index.html` の目録から統合元の項目を取り除き、統合後の項目の `data-len` ・ `e-meta` ・概要と、分野の説明文(`<p class="g-desc">`)を統合後の内容に合わせて更新する。統合元が「読み筋」(02 節)に含まれている場合は、そのリンクも差し替える。他記事(文章技法カタログなど)が統合元ファイルを具体例として参照している場合は、そのリンク・引用元表記も統合後のファイル・章番号に更新する。

## 次のテーマを検討する

`future-article-themes.md` に、既存記事の関心構造から見える「まだ書かれていない角度」がクラスタ別に整理されている。新しい記事の着想が必要な際はまずここを参照し、着手・公開したテーマは同ファイルの完了記録に反映する。

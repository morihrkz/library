仕組みがわかる Web 入門

ウェブサイトの仕組みを知り、独自ドメイン運用にかかる費用を抑える方法

自分のサイトを自分のドメインで持ちたいが、できる限り節約したい。そう思う人のために。

この記事の前提；
独自ドメインでウェブサイトを運用するには、性質の異なる二種類の費用がかかります。ひとつは、サイトのファイルを置いておくサーバー費用。もうひとつは、ドメイン名を保持し続けるためのドメイン維持費用です。この記事で説明するのは、前者のサーバー費用をかけずにできる、静的サイトという仕組みについてです。ドメイン維持費用（目安として年間数百円〜数千円程度）は、どの方法を選んでも、毎年必ず発生します。この点は最初にはっきりさせておきます。

この記事では、次の三つのことを順番に説明します。

この記事でわかること
  1. ブラウザに URL を打ち込んでからページが表示されるまで、裏側で何が起きているか
  2. 動的サイト（ WordPress など）と静的サイトの違い、そしてなぜ多くの人には静的サイトで十分なのか
  3. 実際に、無料の GitHub Pages を使って独自ドメインのサイトを公開する具体的な手順

想定している読者は、ＩＴにそこまで詳しくない一般のかたです。専門用語は出てくるたびに説明します。「なんとなく難しそう」で敬遠していたことが、読み終わる頃には「これ、自分でもできそう」に変わることを目指しています。

先に結論だけ言うと、「ブログや掲示板の様に、誰かが書き込んで内容が変わる仕組み」が要らないサイト（ポートフォリオ・部活紹介・お知らせページなど）なら、静的サイト＋ GitHub Pages の組み合わせで、サーバー費用をかけずに、ドメイン維持費用だけで独自ドメインのサイトを運用できます。
毎月のレンタルサーバー代が要らなくなるという意味です。（一方、ドメイン維持費用は必要です。）

第 1 部ウェブサイトが「見える」仕組み

ふだん何気なく開いているウェブサイトですが、「 URL を打ち込んでからページが表示されるまで」の間に、実はいくつもの通信が発生しています。まずはこの流れを理解しておくと、後半の作業の意味がぐっとわかりやすくなります。

1-1. 住所録としての「 DNS 」

インターネット上のコンピューター（サーバー）は、それぞれ 203.0.113.25 のような数字の羅列である「 IP アドレス」で区別されています。
でも、人間が毎回この数字を覚えて入力するのは大変です。
そこで使われるのが「ドメイン名」、たとえば example.com のような文字の住所です。

ドメイン名と IP アドレスを結びつける、インターネット全体の「電話帳」にあたる仕組みが DNS (Domain Name System) です。
ブラウザは URL を受け取ると、まず DNS に「このドメイン名の IP アドレスは何ですか」と問い合わせ、
答えが返ってきてから、ようやく実際のサーバーに接続しに行きます。

図 1 ： URL を入力してからページが表示されるまでの流れ

1-2. ドメインと、サーバー（ホスティング）は別物

ここが初心者がいちばん混同しやすいポイントです。「ドメイン」と「サーバー（ホスティング先）」は、まったく別の契約・別のサービスです。

役割何をするか例
ドメインサイトの「住所の名前」を持つ権利を、期間を決めて借りるお名前 .com 、 Google Domains 系のレジストラなど
サーバー（ホスティング）実際のファイル（ HTML など）を置いて、リクエストが来たら返すレンタルサーバー、 GitHub Pages など

「このドメイン宛のリクエストは、あのサーバーに届けてね」と DNS に登録することで、両者がつながります。 この「つなぎ方の設定」こそが、後半で説明する DNS 設定の正体です。 逆に言えば、ドメインだけ持っていてもサイトは表示されず、サーバーだけ持っていても独自の名前では呼べません。両方が必要で、それを DNS がつなぐ、というのが全体像です。

第 2 部「動くサイト」と「ただのファイル」の違い

ウェブサイトの作り方には、大きく分けて二つの方式があります。ここを理解すると、「なぜ静的サイトで十分なことが多いのか」が見えてきます。

2-1. 「動的サイト」／「静的サイト」とは

現在、世界中の多くのサイトが WordPress の様な「 CMS （コンテンツ管理システム）」で作られています。これは、ページを見るたびにサーバー内のプログラム（ PHP など）が動き、データベースから記事の内容を取り出して、その場で HTML を組み立てて返す仕組みです。

図 2 ： 動的サイトと静的サイトの、リクエストごとの処理の違い

WordPress は、記事をたくさんの人が投稿したり、コメント機能やお問い合わせフォームを持ったりできる、非常に強力な仕組みです。
ただしその分、サーバー側で PHP やデータベース（ MySQL など）を常時動かしておく必要があり、そのぶんサーバーの管理やセキュリティ対策、そして多くの場合は月額のレンタルサーバー費用が発生します。

2-2. 「静的サイト」で足りることは、実はとても多い

一方、静的サイトは、あらかじめ完成させておいた HTML / CSS / 画像などのファイルを、そのままサーバーに置いておくだけの仕組みです。
誰かがアクセスしてきたら、サーバーは「今から組み立てる」のではなく「もう完成しているファイルをそのまま渡す」だけなので、仕組みとしてはとてもシンプルです。

次のようなサイトには、多くの場合これで十分です。

  • 自分の作品をまとめるポートフォリオサイト
  • 部活動やサークルの紹介ページ
  • イベントの告知ページ
  • プロフィールページ、名刺代わりのサイト
  • 更新頻度が低い、小規模な会社・お店の紹介サイト

「訪問者がコメントを書き込む」「会員登録してログインする」「検索機能や注文機能がある」といった、サーバー側でデータを都度読み書きする必要がある機能がなければ、静的サイトで表現に困ることはほとんどありません。
むしろページの表示速度が速く、セキュリティ上の弱点（例えば WordPress のプラグインの脆弱性を突かれる、といった類のリスク）も原理的に少ないという利点もあります。

2-3. なぜ GitHub Pages は無料で使えるのか

GitHub は、プログラムのソースコードを保存・共有するための世界最大級のサービスです。
GitHub Pages は、その GitHub の中にある「リポジトリ（ファイルの保管庫）」の中身を、そのままインターネット上のウェブサイトとして公開できる機能です。

静的サイトは「ただのファイルを置いて返すだけ」なので、サーバー側の負荷が小さく、 GitHub 社にとってのコストが低いことが、無料で提供できる大きな理由の一つです。個人・非商用利用であれば、容量やアクセス数の制限内で、費用は基本的にかかりません。

つまり、「独自ドメインを取得する費用（年間数百円〜数千円程度）」だけ払えば、サーバー代を一切かけずに、自分だけのドメインでサイトを公開できるということです。これが、この記事で GitHub Pages をおすすめする理由です。

第 3 部実際にやってみよう：架空のウェブサイトを例に

ここからは実践編です。例として、高校生の「なつき」さんが、自分のイラスト作品をまとめたポートフォリオサイトを、独自ドメイン natsuki-works.com （架空の例です）で公開するケースを想定して、手順を追っていきます。

この章で扱う全体の流れ
  1. GitHub アカウントを作り、サイト用のリポジトリを用意する
  2. HTML ファイルを配置し、まずは GitHub 標準の URL (xxxx.github.io) で表示を確認する
  3. 独自ドメインを取得する
  4. DNS の設定で、独自ドメインと GitHub Pages を結びつける
  5. 最終確認（常時 HTTPS 化など）

3-1. 準備するもの

  • パソコン（ Windows でも Mac でも可）
  • メールアドレス（ GitHub アカウント作成用）
  • クレジットカードなど、ドメイン取得費用を支払える手段（保護者の同意・協力を得ることをおすすめします）
注意：ドメインの取得や支払いは、契約行為です。未成年の方は、必ず保護者に相談し、了承を得たうえで進めてください。

Step 1. GitHub アカウントを作り、リポジトリを用意する

1 アカウント作成とリポジトリ作成

github.com にアクセスし、無料アカウントを作成します。ログインしたら、新しいリポジトリ（ファイルの保管場所）を作成します。名前は何でも構いませんが、ここでは natsuki-portfolio とします。

リポジトリを「 Public （公開）」に設定してください。 GitHub Pages で無料公開するには、多くの場合このリポジトリが公開状態である必要があります。

Step 2. サイトのファイルを用意して配置する

2HTML / CSS ファイルを作成

シンプルな構成として、次のようなファイルを用意します。凝ったデザインは後からいくらでも足せるので、まずは表示させることを優先しましょう。

natsuki-portfolio/
├── index.html
├── style.css
└── images/
    └── work1.jpg

index.html の最小限の中身は、たとえばこの様になります。

<!DOCTYPE html>
<html lang="ja">
<head>
  <meta charset="UTF-8">
  <title>なつきの作品集</title>
  <link rel="stylesheet" href="style.css">
</head>
<body>
  <h1>なつきの作品集</h1>
  <p>高校２年生、イラストが好きです。</p>
</body>
</html>

作成したファイルを、 GitHub 上の操作（ブラウザから直接アップロード、または git push コマンド）でリポジトリに追加します。
操作に慣れていない場合は、 GitHub のウェブ画面上にある「 Add file 」→「 Upload files 」から、ファイルをドラッグ & ドロップするだけでも完了します。

Step 3. GitHub Pages を有効化する

3 公開設定を ON にする

リポジトリの「 Settings 」タブ →「 Pages 」の項目を開きます。「 Source 」の設定で、公開したいブランチ（通常は main ）とフォルダ（通常はルート / (root) ）を選び、保存します。

数分待つと、 https://ユーザー名.github.io/natsuki-portfolio/ のような URL でサイトが公開されます。まずはこの標準 URL できちんと表示されるかを確認してください。ここまでは完全に無料で、ドメインもまだ取得していません。

ポイント：独自ドメインの設定は、あくまで「見た目の住所を差し替える」作業です。まずは標準 URL でサイトが正しく動くことを確認してから、次のドメインの話に進むと、トラブルが起きたときに原因を切り分けやすくなります。

Step 4. 独自ドメインを取得する

4 レジストラでドメインを購入

「お名前 .com 」、「 Google Domains 系のサービス」、「 Cloudflare Registrar 」など、ドメインを販売している事業者（レジストラ）で希望のドメイン名（例： natsuki-works.com ）が空いているか検索し、取得（購入）します。

ドメインの種類（ .com / .net / .jp など）によって費用は異なり、年間で数百円〜数千円程度が目安です。
取得すると、そのドメインは基本的に 1 年ごとの更新制になります。
更新を忘れると、ドメインを失効し、最悪の場合は他人に取得されてしまうこともあるため、自動更新の設定を必ず確認しておきましょう。

Step 5. DNS の設定で、ドメインと GitHub Pages をつなぐ

5DNS レコードを設定

ここが第１部で説明した「電話帳」の書き換え作業にあたります。取得したドメインの管理画面（ DNS 設定画面）で、次の 2 種類の設定を行います。

設定するレコード役割
A レコード（四つ）ドメインそのもの（例： natsuki-works.com ）を、 GitHub Pages の IP アドレスに向ける
CNAME レコードwww.natsuki-works.com のような別名を、 xxxx.github.io に向ける

GitHub Pages 用の A レコードの IP アドレスは、 GitHub の公式ドキュメントに記載されている固定値を使います。
（執筆時点の値の例として、 185.199.108.153 のような 4 つのアドレスが案内されています。実際に設定する際は、必ず GitHub 公式の最新情報を確認してください）。

あわせて、 GitHub 側のリポジトリ設定（ Settings → Pages → Custom domain ）に、使いたいドメイン名を入力して保存します。
この「 GitHub 側の設定」と「 DNS 側の設定」は、両方が揃って初めて機能します。片方だけでは正しく表示されません。

反映には時間がかかることがあります
DNS の設定変更は、インターネット全体にすぐ行き渡るわけではありません。数分で反映されることもあれば、数時間〜最大 24 〜 48 時間ほどかかることもあります。設定直後にうまく表示されなくても、あわてずに時間をおいて再確認しましょう。

Step 6. 常時 HTTPS 化を有効にする

6 最終確認

独自ドメインでの表示が確認できたら、 GitHub の Pages 設定画面で「 Enforce HTTPS 」のチェックボックスを有効にします。
これにより、 http:// でアクセスされた場合も自動的に安全な https:// に転送されるようになり、ブラウザの警告表示も避けられます。
この項目は、 DNS の設定が正しく反映されるまで有効化できないことがあります。反映を待ってから設定してください。）

3-2. つまずきやすいポイント

  • DNS の反映待ちを、設定ミスと勘違いしてしまう：まずは時間を置いて再確認する
  • A レコードと CNAME を混同する：ドメイン本体には A レコード、 www 付きには CNAME 、と役割が違うことを覚えておく
  • GitHub 側の Custom domain 設定を忘れる： DNS だけ設定しても、 GitHub 側にドメイン名を伝えていないと正しく機能しない
  • ドメインの自動更新を切ってしまい、失効させる：年に一度の更新は、カレンダーにリマインダーを入れておくと安心

まとめ

最後に、この記事の内容を振り返ります。

  • ウェブサイトが表示されるまでには、「 DNS でドメインから IP アドレスを調べる」→「そのサーバーにリクエストを送る」→「返ってきたファイルをブラウザが描画する」という流れがある
  • WordPress のような動的サイトは、アクセスのたびにサーバー側でページを組み立てる。一方、静的サイトはあらかじめ完成したファイルをそのまま返すだけなので、仕組みがシンプルで、 GitHub Pages のような無料ホスティングとも相性が良い
  • コメント機能や会員機能が要らないサイトなら、静的サイト＋ GitHub Pages ＋独自ドメインという組み合わせで、月額のサーバー費用をかけずに運用できる

「自分の作品を、自分の名前のドメインで世界に公開する」というのは、思っているよりずっと手の届く範囲にあります。この記事をきっかけに、まずは GitHub アカウントを作るところから、一歩踏み出してみてください。

本記事は、実際のウェブサイト移行作業の経験をもとに、静的サイトと GitHub Pages の仕組みを一般化して解説したものです。ドメインの取得や DNS 設定の具体的な項目名・画面表示は、利用するサービスによって多少異なる場合があります。実際の作業前には、各サービスの公式ドキュメントもあわせて確認してください。

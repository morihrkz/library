Claude Code 環境移植ガイド（Windows 11 ⇔ Mac）

元記事:個人サイト『書庫』所収の実践ガイド。 Claude Code の設定・記憶を別 PC へ移すためのチェックリスト。全 7 章・約 7 分。 2026 年 8 月時点の公式ドキュメントに基づく。

Claude Code の設定は「ユーザー設定」「プロジェクト設定」「認証」「 MCP サーバー」「補助ツール（Node.js 等）」の 5 系統に分かれている。 CLAUDE.md の上書きコピーはそのうちの一部（ユーザー記憶）に過ぎない。以下、優先度の高い順に並べている。

▶ をタップすると展開します。同じ階層では一つ開くと他は閉じます（「すべて展開」時を除く）。

全プロジェクト共通で効く、あなた個人の設定である。ホームディレクトリ配下にあるため、これが「移植の本丸」になる。

ファイル / ディレクトリ内容移植方法
~/.claude/CLAUDE.md グローバルなメモリ。プロジェクト横断で常に読み込まれる指示・好み 同じ相対パスにファイルをコピー
~/.claude/settings.json 権限（許可 / 拒否コマンド）、環境変数、モデル既定値などユーザー設定 同じ相対パスにコピー。中身は JSON なのでそのまま持っていける
~/.claude/commands/ カスタムスラッシュコマンド（.md ファイル群） ディレクトリごとコピー
~/.claude/agents/ カスタムサブエージェント定義（YAML frontmatter 付き Markdown） ディレクトリごとコピー
~/.claude/output-styles/ 出力スタイル設定 ディレクトリごとコピー
~/.claude/keybindings.json キーバインドの上書き設定（存在する場合のみ） コピー
🪟 Windows 11 の実パス %USERPROFILE%\.claude\
例： C:\Users\あなたの名前\.claude\
🍎 macOS の実パス ~/.claude/
例： /Users/あなたの名前/.claude/
コピー方法の一例（.claude フォルダごと） Windows 側の %USERPROFILE%\.claude フォルダを ZIP 化 → Mac 側で解凍し ~/.claude に配置、で個別ファイルを気にせず一括移植できる。 settings.json 内のパスが OS 依存の値（後述の環境変数など）を含む場合は、コピー後に中身を確認する必要がある。

1 ログインセッション（OAuth）

ログイン状態は ~/.claude.json に保存されているが、トークンを直接コピーするのは推奨されない（環境・デバイス依存のため失効やセキュリティリスクがある）。新 PC では claude login（またはコンソール上の OAuth フロー）で再ログインするのが確実である。

2API 課金運用の場合

API 直接課金で使っている場合は ANTHROPIC_API_KEY 環境変数、または settings.json の env ブロックや apiKeyHelper（外部スクリプトでキーを都度取得する仕組み）を移植する。

// settings.json の env ブロック例
{
  "env": {
    "ANTHROPIC_API_KEY": " （新PCでは環境変数側で管理し、ここには書かないのが安全） "
  }
}
⚠️ API キーそのものをファイルに書いて渡すのは避ける API キーは OS の環境変数やシークレット管理（Windows なら「システム環境変数」、 Mac ならシェルの ~/.zshrc 等）に個別設定し、設定ファイルには直接書き込まない運用が安全である。

各リポジトリ（プロジェクトフォルダ）内にある設定である。 Git リポジトリならクローンするだけで自動的に付いてくる。

ファイルスコープGit 管理
CLAUDE.md
（または .claude/CLAUDE.md）		 プロジェクト固有の指示。チーム共有 する（コミット対象）
.claude/settings.json チームで共有する権限設定・ MCP 設定など する
.claude/settings.local.json 個人限定の上書き設定（実験用など） しない（gitignore 対象） - 手動で移植が必要
.claude/agents/ プロジェクト専用サブエージェント する
CLAUDE.local.md 個人用のプロジェクトメモ しない - 手動で移植が必要
.mcp.json プロジェクトスコープの MCP サーバー定義 する（次項参照）
実質的にやること Git で管理されているリポジトリなら「新 PC で git clone 」するだけで大部分は再現される。注意すべきは gitignore 対象になっている個人ファイル（settings.local.json 、 CLAUDE.local.md）で、これらは手動でコピーしない限り引き継がれない。

MCP （Model Context Protocol）サーバーの登録先はスコープによってファイルが異なる。

スコープ保存場所備考
ユーザー ~/.claude.json OAuth セッション、プロジェクトごとの許可状態、キャッシュも同居
プロジェクト .mcp.json リポジトリ直下。 Git でチーム共有可能
ローカル（個人×プロジェクト） ~/.claude.json 内 プロジェクトごとの個人設定として格納
再登録という選択肢 claude mcp list で現在登録されている MCP サーバー一覧を確認し、新 PC 側で claude mcp add を使って再登録するほうが、認証まわりのトラブルが少なく確実である。設定ファイルを直接コピーする場合は、サーバーによっては個別の認証（トークンなど）が別途必要になることがある。
⚠️ Auto Memory はマシンローカルで、原則「移植されない」 Claude Code にはユーザーが書く CLAUDE.md とは別に、 Claude が会話中に自動で学習内容を書き留める「 Auto Memory 」機能がある（デフォルト ON）。保存先は リポジトリごと・マシンごと に分かれており、 ~/.claude/projects/<プロジェクト名>/memory/ に置かれる。この機能はプロジェクトに紐づいたローカルの学習内容であり、他の PC へは自動的に引き継がれない。重要な決定事項が書かれていた場合は、内容を確認してプロジェクトの CLAUDE.md など永続的なファイルへ手動で書き写すことが推奨される。

セッション中に /memory コマンドを実行すると、現在読み込まれている CLAUDE.md ・ CLAUDE.local.md ・ Auto Memory の場所を一覧表示できるので、移植前に新旧環境で見比べると確実である。

  • Claude Code 自体は npm 経由でグローバルインストールするツールのため、新 PC では npm install -g @anthropic-ai/claude-code を実行し直す
  • Node.js のバージョンが前提要件を満たしているか確認（新 PC で未インストールなら Node.js 自体のセットアップも必要）
  • シェル補完（bash/zsh/PowerShell）を設定していた場合は、それぞれの環境向けに再設定
  • Windows/Mac 双方に Node.js と npm install -g @anthropic-ai/claude-code で Claude Code 本体を用意する
  • ~/.claude/CLAUDE.md をコピー（%USERPROFILE%\.claude\CLAUDE.md ⇔ ~/.claude/CLAUDE.md）
  • ~/.claude/settings.json をコピーし、中身のパス・環境変数が OS 依存でないか確認
  • ~/.claude/commands/ 、 ~/.claude/agents/ 、 ~/.claude/output-styles/ をまとめてコピー
  • 新 PC で claude login を実行し再ログイン（トークンの直接コピーはしない）
  • API 課金運用なら ANTHROPIC_API_KEY を新 PC の環境変数として設定
  • プロジェクトは Git で clone し、 .claude/settings.local.json ・ CLAUDE.local.md があれば個別にコピー
  • claude mcp list で登録済み MCP サーバーを確認し、新 PC 側で claude mcp add により再登録（または .mcp.json ／ ~/.claude.json をコピー）
  • 旧 PC で /memory を実行し、 Auto Memory の中に永続化すべき内容がないか確認・手動転記
  • 新 PC で /status または /doctor を実行し、設定が正しく読み込まれているか検証
検証コマンド 移植後は /status（読み込まれた設定ソースの一覧）や claude doctor（設定の妥当性チェック）を実行すると、意図した設定ファイルが実際に読み込まれているか確認できる。
